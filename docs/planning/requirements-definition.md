# 要件定義書

## 1. システム概要

### 1.1 文書の目的

本書は、設備点検管理システム（Equipment Inspection System）の機能要件、非機能要件および運用上の制約条件を明確にすることを目的とする。

本書で定義した要件を、後続の設計、実装およびテストの基準とする。

### 1.2 システムの目的

本システムは、設備情報、点検項目および点検結果を一元管理し、設備点検業務の効率化と記録の標準化を図るWebアプリケーションである。

従来の紙やExcelによる管理で発生する情報の分散、過去の点検履歴の検索負担、設備ごとの点検項目の管理負担を軽減する。

### 1.3 想定利用者

本システムでは、以下の2種類の利用者を想定する。

| 利用者                  | 役割                                                   |
| ----------------------- | ------------------------------------------------------ |
| ADMIN（設備管理者）     | 設備情報および点検項目の管理、点検履歴の確認           |
| INSPECTOR（点検担当者） | 設備の選択、点検の実施、点検結果の登録および履歴の確認 |

利用者ごとの詳細な操作権限は、第3章「権限要件」で定義する。

### 1.4 対象業務

本システムでは、以下の業務を対象とする。

1. 設備情報の登録・管理
2. 設備ごとの点検項目の登録・管理
3. 点検対象設備の選択
4. 点検の実施および結果の登録
5. 過去の点検履歴の確認
6. 設備管理者による点検結果および異常記録の確認

なお、異常発見後の修理対応や修理進捗の管理は対象外とする。

## 2. 機能要件

### 2.1 概要

本章では、設備点検管理システムが提供する機能および業務上のルールを定義する。

各機能要件には、識別および追跡を目的として `FR-XXX` 形式の要件IDを付与する。

利用者ごとの詳細な操作権限は、第3章「権限要件」で定義する。

### 2.2 認証機能

| 要件ID | 機能要件                                                                     |
| ------ | ---------------------------------------------------------------------------- |
| FR-001 | 登録済みの利用者がユーザー名およびパスワードを使用してログインできること。   |
| FR-002 | 認証されていない利用者による、認証が必要な機能へのアクセスを制限できること。 |
| FR-003 | ログイン済みの利用者がログアウトできること。                                 |

### 2.3 設備管理機能

| 要件ID | 機能要件                                                   |
| ------ | ---------------------------------------------------------- |
| FR-004 | 設備情報を新規登録できること。                             |
| FR-005 | 登録済みの設備情報を一覧表示できること。                   |
| FR-006 | 登録済みの設備情報の詳細を確認できること。                 |
| FR-007 | 登録済みの設備情報を編集できること。                       |
| FR-024 | 設備情報を物理削除せず、「廃止」状態に変更できること。     |
| FR-025 | 廃止された設備を通常の点検対象一覧から除外できること。     |
| FR-026 | 廃止された設備の情報および過去の点検履歴を確認できること。 |

設備情報の削除可否および削除時の点検履歴の扱いについては、別途決定する。

### 2.4 点検項目管理機能

| 要件ID | 機能要件                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------ |
| FR-008 | 設備ごとに点検項目を登録できること。                                                                   |
| FR-009 | 設備に紐づく点検項目を一覧表示できること。                                                             |
| FR-010 | 設備に紐づく点検項目の内容を確認できること。                                                           |
| FR-027 | 登録済みの点検項目を編集できること。                                                                   |
| FR-028 | 登録済みの点検項目を物理削除せず、無効化できること。                                                   |
| FR-029 | 無効化された点検項目を、新規の点検対象から除外できること。                                             |
| FR-030 | 点検項目を編集・無効化した場合も、過去の点検結果を当時の項目内容および判定基準とともに確認できること。 |

点検項目の編集・削除には、過去の点検結果との整合性を維持する方式を採用する。

点検項目を削除する場合は論理削除とし、過去の点検結果およびその記録時点の項目内容を保持する。

### 2.5 点検実施・結果登録機能

| 要件ID | 機能要件                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------- |
| FR-011 | 点検担当者が点検対象の設備を選択できること。                                                   |
| FR-012 | 選択した設備に設定されている点検項目を確認できること。                                         |
| FR-013 | 点検項目ごとに点検結果を入力できること。                                                       |
| FR-014 | 入力した点検結果を設備と関連付けて登録できること。                                             |
| FR-015 | 異常が確認された点検結果を記録できること。                                                     |
| FR-031 | 登録済みの点検結果を訂正できること。                                                           |
| FR-032 | 登録済みの点検結果を取り消せること。                                                           |
| FR-033 | 点検結果の訂正・取消時に、変更前の記録を保持できること。                                       |
| FR-034 | 点検結果の訂正・取消について、実施者、実施日時、変更内容および理由を記録できること。           |
| FR-035 | 点検履歴から、点検結果の訂正・取消履歴を確認できること。                                       |
| FR-036 | 点検項目ごとに、目視点検または数値測定の判定方式を設定できること。                             |
| FR-037 | 目視点検では、点検担当者がOKまたはNGを手動で選択できること。                                   |
| FR-038 | 数値測定では、点検担当者が測定値を入力できること。                                             |
| FR-039 | 数値測定では、点検項目に設定された判定基準に基づき、システムがOKまたはNGを自動判定できること。 |
| FR-040 | 点検結果がNGの場合、異常内容のコメントを入力できること。                                       |
| FR-041 | 点検結果の登録時に、必須入力項目が満たされていることを検証できること。                         |
| FR-042 | 点検結果の登録時に、点検日時をシステムが自動記録できること。                                   |
| FR-043 | 点検結果の登録時に、認証済みの点検担当者をシステムが自動記録できること。                       |

目視点検ではOK・NGの選択を必須とし、数値測定では測定値の入力を必須とする。

点検結果がNGの場合は、異常内容のコメントを必須とする。

数値測定の判定基準は点検項目に設定し、点検実施時点の判定基準を履歴として保持する。

### 2.6 点検履歴確認機能

| 要件ID | 機能要件                                                                   |
| ------ | -------------------------------------------------------------------------- |
| FR-016 | 過去に登録された点検履歴を一覧表示できること。                             |
| FR-017 | 点検履歴の詳細を確認できること。                                           |
| FR-018 | 設備ごとの点検履歴を確認できること。                                       |
| FR-019 | 記録された異常を確認できること。                                           |
| FR-044 | 点検履歴を設備名で検索できること。設備名は部分一致検索に対応すること。     |
| FR-045 | 点検履歴を点検日時の開始日・終了日で絞り込めること。                       |
| FR-046 | 点検履歴を判定結果（OK・NG）で絞り込めること。                             |
| FR-047 | 点検履歴を点検担当者で絞り込めること。                                     |
| FR-048 | 複数の検索・絞り込み条件を組み合わせて点検履歴を検索できること。           |
| FR-049 | 検索条件を指定しない場合、点検履歴を新しい順に一覧表示できること。         |
| FR-050 | 点検履歴一覧をページ単位で表示し、ページを切り替えられること。             |
| FR-051 | 検索条件に一致する点検履歴が存在しない場合、その旨を画面に表示できること。 |

点検履歴の検索・絞り込み機能は、ADMINおよびINSPECTORの両方が利用できること。

検索結果から点検履歴の詳細を参照でき、訂正・取消履歴についても既存の機能要件に従って確認できること。

| BR-011   | 廃止された設備は、新規の点検対象として選択できない。                                                                       |
| BR-012   | 設備を廃止した場合も、過去の点検履歴および関連する設備情報を保持する。                                                     |

## 3. 権限要件

### 3.1 概要

本章では、設備点検管理システムにおける利用者の役割および操作権限を定義する。

本システムでは、役割に応じたアクセス制御を採用し、利用者が許可された機能のみを利用できるようにする。

### 3.2 ユーザーの役割

本システムでは、以下の2種類のロールを定義する。

| ロール    | 名称       | 役割                                                           |
| --------- | ---------- | -------------------------------------------------------------- |
| ADMIN     | 設備管理者 | 設備情報および点検項目の管理、点検履歴の確認を行う。           |
| INSPECTOR | 点検担当者 | 設備の選択、点検の実施、点検結果の登録および履歴の確認を行う。 |

なお、ユーザーアカウントの初期登録はシステム運用者が行い、ADMINおよびINSPECTORにはアカウント管理権限を付与しない。

## 4. 非機能要件

### 4.1 概要

本章では、設備点検管理システムに求められる性能、可用性、セキュリティ、データ保全性および保守性に関する要件を定義する。

各非機能要件には、識別および追跡を目的として `NFR-XXX` 形式の要件IDを付与する。

本システムは小規模な設備点検業務を想定したWebアプリケーションであり、常時稼働や大規模アクセスへの対応を前提としない。

### 4.2 性能要件

| 要件ID  | 非機能要件                                                                                   |
| ------- | -------------------------------------------------------------------------------------------- |
| NFR-001 | 一般的なPCブラウザから、設備情報および点検履歴を支障なく閲覧・操作できること。               |
| NFR-002 | 設備登録、点検結果登録などの主要操作について、利用者が処理の成功または失敗を確認できること。 |
| NFR-003 | 想定する利用者数およびデータ量に対して、主要機能が正常に動作すること。                       |

具体的な応答時間、同時利用者数および想定データ量については、運用規模を踏まえて別途決定する。

### 4.3 可用性要件

| 要件ID  | 非機能要件                                                           |
| ------- | -------------------------------------------------------------------- |
| NFR-004 | システムは、必要な期間に起動して利用できる構成とすること。           |
| NFR-005 | システムの停止および再起動を、所定の運用手順に従って実施できること。 |
| NFR-006 | システム起動後、主要機能が正常に利用できることを確認できること。     |

本システムは常時稼働を前提とせず、デモおよび動作確認に必要な期間のみ稼働させる。

そのため、24時間365日の稼働保証や厳格な稼働率目標は設定しない。

### 4.4 セキュリティ要件

| ------- | ------------------------------------------------ |

## 5. 運用・制約条件

### 5.1 概要

本章では、設備点検管理システムの運用方法、利用者アカウントの管理方針、システム環境の管理および開発範囲に関する制約条件を定義する。

本システムは、小規模な設備点検業務を想定したWebアプリケーションであり、必要な期間にシステムを稼働させる運用を前提とする。

### 5.2 アカウント運用

| 要件ID | 運用要件                                                                                   |
| ------ | ------------------------------------------------------------------------------------------ |
| OP-001 | 利用者アカウントの初期登録は、システム運用者が実施すること。                               |
| OP-002 | 初期登録は、専用の初期ユーザー作成スクリプトを使用して実施できること。                     |
| OP-003 | 初期登録するアカウントには、ADMINまたはINSPECTORのロールを設定できること。                 |
| OP-004 | 初期登録時のパスワードは、安全なハッシュ化処理を行って保存すること。                       |
| OP-005 | 初期登録に必要なパスワードなどの機密情報を、スクリプトやソースコードに直接記載しないこと。 |

初期登録後のアカウント情報変更・無効化については、別途決定する。

### 5.3 システムの起動・停止

| 要件ID | 運用要件                                                                          |

| OP-007 | システム運用者が、所定の手順に従ってAWS環境を起動・停止できること。               |
| OP-008 | AWS環境の停止・再構築時に、必要な業務データを保持または復元できること。           |

## 6. 未決定事項

### 6.1 概要

本章では、要件定義時点で方針が確定していない事項を整理する。

未決定事項には `TBD-XXX` 形式の識別IDを付与し、検討内容、関連要件および決定時期を管理する。

各事項について方針が確定した場合は、関連する要件および業務ルールに反映する。

これらの事項は、機能の提供範囲や業務上の操作に影響するため、原則として詳細設計・実装前に方針を確定する。

### 6.3 認証・アカウント管理に関する未決定事項

| ID      | 未決定事項                                   | 関連要件                  |
| ------- | -------------------------------------------- | ------------------------- |
| TBD-007 | 初期登録後のアカウント情報変更・無効化の方法 | OP-001〜005               |
| TBD-008 | 認証状態の維持方法およびセッションの有効期間 | FR-001〜003、NFR-007〜008 |

認証・アカウント管理については、利用者の操作範囲とセキュリティ要件を踏まえて方針を決定する。

### 6.4 非機能要件に関する未決定事項

| ID      | 未決定事項                           | 関連要件     |
| ------- | ------------------------------------ | ------------ |
| TBD-009 | 主要操作の応答時間の目標値           | NFR-001〜003 |
| TBD-010 | 想定する同時利用者数およびデータ量   | NFR-003      |
| TBD-011 | 対応ブラウザおよび対応バージョン     | NFR-021〜023 |
| TBD-012 | バックアップの取得頻度および保存期間 | NFR-015〜016 |
| TBD-013 | データ復旧に関する目標値             | NFR-014〜016 |
| TBD-014 | ログの保存期間および監視範囲         | NFR-019      |

これらの事項は、想定する利用規模、運用方法およびコストを考慮して決定する。

### 6.5 運用・保守に関する未決定事項

| ID      | 未決定事項                          | 関連要件    |
| ------- | ----------------------------------- | ----------- |
| TBD-015 | AWS環境の起動・停止手順の自動化範囲 | OP-006〜009 |
| TBD-016 | アプリケーション更新後の確認手順    | OP-010〜011 |
| TBD-017 | 障害発生時の対応手順                | OP-012〜013 |

具体的な実施手順については、関連する設計書または運用手順書で定義する。

### 6.6 未決定事項の管理方針

未決定事項は、以下の方針で管理する。

1. 各事項に識別IDを付与し、関連要件との対応関係を維持する。
2. 機能範囲や業務ルールに影響する事項は、原則として実装前に決定する。
3. 設計・運用手順に関する詳細事項は、関連文書で決定することを認める。
4. 決定した事項は、関連する要件および業務ルールへ反映する。
5. 未決定事項が残る場合は、対象範囲と今後の対応方針を明確にする。

### 6.7 要件定義の確定条件

本書は、以下の条件を満たした段階で確定する。

1. システムの主要な機能要件が明確になっていること。
2. ADMINおよびINSPECTORの操作権限が定義されていること。
3. 主要な非機能要件および運用上の制約条件が定義されていること。
4. 実装範囲に影響する未決定事項について、方針が決定されていること。
5. 残存する未決定事項について、決定時期または対応方針が明確になっていること。
6. 要求整理書との重大な不整合がないこと。

上記の条件を満たした後、要件定義書を確定し、後続の設計・実装との整合性を確認する。

## 補足：要件ID・略語一覧

本書で使用する要件IDおよび略語を以下に示す。

| 略語 | 正式名称                   | 説明                                                       |
| ---- | -------------------------- | ---------------------------------------------------------- |
| FR   | Functional Requirement     | 機能要件。システムが提供する機能を定義する。               |
| NFR  | Non-Functional Requirement | 非機能要件。性能、可用性、セキュリティなどを定義する。     |
| BR   | Business Rule              | 業務ルール。システムが従う業務上の規則を定義する。         |
| OP   | Operational Requirement    | 運用要件。システムの運用および保守に関する要件を定義する。 |
| C    | Constraint                 | 制約・前提条件                                             |
| O    | Out of Scope               | 対象外の要求                                               |
| TBD  | To Be Determined           | 未決定事項                                                 |

### 要件IDの命名規則

各要件IDは、以下の形式で採番する。

`<略語>-<3桁の連番>`

例：

- `FR-001`：機能要件の1番目
- `NFR-001`：非機能要件の1番目
- `BR-001`：業務ルールの1番目
- `OP-001`：運用要件の1番目

要件IDは識別・追跡に使用し、既存のIDは原則として再利用しない。
