# AWS投入前 Docker環境 総合確認結果

## 概要

AWS環境へのデプロイに進む前に、ローカルのDocker環境でSpring BootアプリケーションおよびPostgreSQLを起動し、主要機能、データ永続化、コンテナ間通信、ビルド・テストの総合確認を実施した。

本確認は GitHub Issue #75「Docker環境でAWS投入前の総合確認を実施する」のAcceptance Criteriaに基づいて実施した。

| -------------------------------------------------------------------- | ---- |
| 最新のアプリケーションからDocker Imageをビルドできる                 | OK   |
| PostgreSQLコンテナが正常に起動し、healthy状態になる                  | OK   |
| Spring Bootアプリケーションコンテナが正常に起動する                  | OK   |

| 登録した点検履歴を正常に参照できる                                   | OK   |
| アプリケーションコンテナ再起動後も登録済みデータが保持される         | OK   |

## Docker Image・コンテナ起動確認

最新のアプリケーションからDocker Imageをビルドし、Docker環境でSpring BootアプリケーションおよびPostgreSQLを起動した。

確認時には以下の状態となった。

- Spring Bootアプリケーションコンテナが起動状態であることを確認
- PostgreSQLコンテナが起動し、`healthy` 状態であることを確認
- Spring BootアプリケーションからPostgreSQLへ接続できることを確認
- ホストのブラウザからSpring Bootアプリケーションへアクセスできることを確認

## 主要機能の動作確認

Docker環境上で以下の主要機能を確認した。

- 初期ユーザーによるログイン
- 設備情報の参照
- 点検処理の実行
- 点検結果の登録
- 登録済み点検履歴の参照

いずれも正常に動作することを確認した。

## データ永続化確認

点検結果を新規登録した後、Spring Bootアプリケーションコンテナを再起動した。

再起動後も登録した点検履歴がPostgreSQLに保持されており、アプリケーションから参照できることを確認した。

PostgreSQL上では、確認時点で以下の点検履歴が保持されていた。

```text
inspection id: 1
equipment_id: 1
user_id: 1
comment: edefa
```
